# TaskMaster

Telegram-бот и Mini App для задач, приватных проектов и небольших команд. Архитектура и API-контракты описаны в [docs/architecture.md](docs/architecture.md).

## Что работает

- Регистрация через Telegram, приватные проекты, приглашения по ID, username и одноразовой ссылке.
- Задачи с ключами, описанием Markdown, приоритетом, исполнителем, дедлайном, мягким удалением и восстановлением.
- Собственные статусы, завершающие статусы, порядок колонок, Kanban с перемещением мышью и касанием, список, поиск и фильтры.
- Комментарии, чек-листы, вложения PNG/JPG/WEBP/PDF/TXT до 10 МБ и история изменений.
- Необязательные спринты с датами, запуском, завершением и сохранённым результатом.
- Серверный таймер с паузой и остановкой, ручное время, история и суммы по проектам.
- Настройки уведомлений по проекту и пользователю, постоянная очередь с повторами и напоминания о сроках.
- Ручная связь с PR и коммитами, репозитории с зашифрованным fine-grained token, подписанные webhooks и защита от повторной обработки.
- Светлая и тёмная темы Telegram, безопасные отступы и Back Button.

## Новая установка

Нужны Docker, Compose и HTTPS-прокси. Бот работает через long polling, отдельный Telegram webhook не нужен. Одновременно запускайте только один polling-процесс с данным токеном.

1. Скопируйте `.env.example` в `.env`. Заполните BOT_TOKEN и BOT_USERNAME из BotFather, APP_URL и DATABASE_URL.
2. Сгенерируйте случайный пароль PostgreSQL и SECRET_KEY, а ENCRYPTION_KEY командой `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`.
3. Права на `.env`: `chmod 600 .env`. Файл исключён из Git и сборочного контекста.
   Если Telegram недоступен из Docker, задайте BOT_PROXY, например `http://host.docker.internal:2081`, для доступного HTTP-прокси сервера.
4. Создайте или укажите внешнюю Docker-сеть прокси в PROXY_NETWORK. Подключите к ней Caddy.
5. Добавьте маршрут из `ops/Caddyfile.example`. Если используется другой путь, одинаково измените BASE_PATH, APP_URL и маршрут прокси.
6. Выполните `docker compose build api` и `docker compose up -d api bot worker`. Compose запустит PostgreSQL, Redis и миграции автоматически.
7. Проверьте `docker compose ps` и `curl https://example.com/taskmaster/health`. Ожидается `{"status":"ok"}`.

Frontend собирается внутри образа, отдельный Node-процесс в production не используется. Для локальной сборки: `npm ci --prefix frontend` и `npm run build --prefix frontend`.

## Telegram и Mini App

Команды и кнопка меню настраиваются ботом при запуске. Основные команды: `/projects`, `/tasks`, `/today`, `/new`, `/timer`, `/help`, `/cancel`.

Текстовый парсер поддерживает только документированные формулировки:

- `Создай задачу исправить авторизацию завтра`
- `Добавь задачу обновить API в проект Altair`
- `Создай задачу релиз 2026-10-20 в проект ALT`
- `Покажи мои задачи на сегодня`
- `Заверши ALT-12`
- `Начни работу над KDR-8`

Дата: сегодня, завтра, послезавтра, ГГГГ-ММ-ДД или ДД.ММ.ГГГГ. Дата стоит в конце заголовка, перед указанием проекта. Создание и переходы статуса подтверждаются кнопкой. Если несколько подходящих проектов или статусов, бот предлагает выбрать.

initData проверяется сервером по HMAC и времени выдачи. После часа работы приложение нужно открыть заново через бота. Обычная ссылка в браузере показывает экран входа, данные не выдаются. Опционально в BotFather можно настроить Main Mini App с тем же HTTPS URL.

## GitHub

В настройках проекта укажите `owner/repository`. Для приватного репозитория используйте fine-grained personal access token с доступом к выбранному репозиторию. Приложение проверяет доступ к репозиторию и шифрует токен в PostgreSQL. Не меняйте ENCRYPTION_KEY без миграции зашифрованных данных.

После подключения скопируйте показанные Payload URL и Secret в GitHub: Repository Settings, Webhooks, Add webhook. Content type: `application/json`, события: Push и Pull requests. Secret показывается только в результате подключения. При утрате отключите репозиторий и подключите заново, затем обновите webhook в GitHub. Отключение удаляет сохранённый токен и меняет секрет.

Ключ задачи в сообщении коммита, заголовке или описании PR связывает событие с задачей: `fix(ALT-12): resolve login issue`. Статус задачи автоматически не меняется. Ручная связь доступна в карточке задачи. Проверка подписи следует [документации GitHub](https://docs.github.com/en/webhooks/using-webhooks/validating-webhook-deliveries), проверка initData следует [документации Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).

## Проверки

Тесты требуют отдельную PostgreSQL-базу с именем, заканчивающимся на `_test`. Они никогда не очищают production-базу. Создайте `taskmaster_test` через `docker compose exec db createdb -U taskmaster taskmaster_test`, затем передайте TEST_DATABASE_URL при запуске `docker compose --profile test run --rm test`. Формат URL такой же, как DATABASE_URL, с другим именем базы. Секреты не передавайте в командной строке, используйте локальный защищённый файл окружения или программный запуск.

Проверяются авторизация, доступ к чужим проектам, задачи, конфликты изменений, приглашения, статусы, спринты, таймер, восстановление данных в новом соединении, файлы, уведомления, повторы, подпись и дедупликация GitHub, конкурентное создание задач.

## Эксплуатация

`docker compose logs --tail=100 api bot worker` показывает текущие ошибки. Логи ограничены по размеру. `docker compose restart api bot worker` перезапускает приложение без удаления базы, файлов и Redis. Таймеры продолжают отсчитывать время по сохранённой серверной метке. Уведомления сохраняются в PostgreSQL, повторы используют увеличение задержки. После 12 неудачных попыток уведомление отмечается как failed; их можно просмотреть в базе. При запрете сообщений ботом уведомление также считается failed.

Health checks PostgreSQL, Redis и API проверяют доступность. Для bot и worker проверяется жизнь процесса; это не является полной проверкой доступности Telegram. Compose использует restart unless-stopped. Отдельная автоматизация мониторинга не настроена.

Реализована доставка уведомлений не менее одного раза. Сбой между отправкой в Telegram и записью результата может вызвать повтор, поскольку Telegram не предоставляет ключ идемпотентности для sendMessage. Сканирование дедлайнов происходит раз в 5 минут, одно напоминание каждого типа в день. Ранее не отправленные задачи очереди продолжаются после перезапуска. Список задач ограничен 1000 записями на запрос, история активности 300, детали дочерних записей 500. Для проектов выше этих объёмов понадобится пагинация.

## Резервное копирование и восстановление

Запустите `sh ops/backup.sh /home/komarrick/taskmaster-backups`. Скрипт кратко останавливает API, bot и worker, создаёт PostgreSQL dump, архив вложений и копию окружения, затем возвращает сервисы. Redis хранит только состояния диалогов и лимиты запросов; задачи, таймеры и уведомления находятся в PostgreSQL. Архив содержит секреты, права каталога закрытые. Храните дополнительную копию вне сервера в зашифрованном виде.

Восстановление перезаписывает данные и требует отдельного решения оператора. Сначала сделайте новый backup текущего состояния. Остановите API, bot и worker; восстановите нужное окружение с ENCRYPTION_KEY, PostgreSQL dump через `pg_restore --clean --if-exists`, и архив в volume attachments. Владелец файлов должен иметь UID 10001. Выполните миграции `docker compose run --rm migrate`, затем запустите API, bot и worker и проверьте /health. Не используйте `docker compose down -v`, если данные должны сохраняться.

# Мои дела

Личный диспетчер в Telegram. Отправьте обычный текст или голосовое: «Через неделю сдать проект по вышмату». Бот сохранит дело, предложит время напоминания и частоту повторов.

Бот: [@taskovio_bot](https://t.me/taskovio_bot). Список дел открывается кнопкой меню «Мои дела».

## Ежедневное использование

1. Отправьте дело текстом. Слова «создай задачу» и выбор проекта не нужны.
2. Для голосового бот покажет текст и срок. Нажмите «Сохранить» или «Исправить».
3. Выберите, когда напомнить: через час, завтра в 09:00, за день или за 3 дня до срока, в день срока или в своё время.
4. Выберите повтор: один раз, каждый час, каждый день, каждые 3 дня или каждую неделю.
5. Нажмите «Готово», когда закончили. Повторные напоминания остановятся. Из уведомления можно отложить напоминание на час или отключить его.

В Mini App только три списка: Входящие, Сегодня, Позже. Дело можно добавить одной строкой, выполнить одним нажатием, открыть для изменения срока и напоминания. Выполненные доступны отдельно. Просроченные дела остаются в списке Сегодня.

Часовой пояс: Москва. Дата без времени означает срок до конца дня. Напоминание задаётся отдельно от срока. Указанное время видно перед сохранением.

## Даты и голос

Примеры: «завтра», «через неделю», «через две недели», «в пятницу», «25 октября», «двадцать пятого октября», «01.11.2026», «завтра в 18:30», «через полчаса».

Бот использует ограниченный детерминированный разбор даты. Несколько альтернативных сроков, некорректная дата или неподдерживаемое выражение требуют уточнения. Проверьте показанный срок. Неясная дата не подменяется случайной.

Голосовые: до 2 минут и 5 МБ, русский язык. Распознавание выполняет Vosk на домашнем сервере. Платный API и ключ распознавания не нужны. Аудио скачивается во временный каталог и удаляется после обработки, текст остаётся в базе. Ошибку распознавания можно исправить перед сохранением. Модель: [vosk-model-small-ru-0.22](https://alphacephei.com/vosk/models), лицензия Apache 2.0.

## Запуск

Нужны Docker Compose и HTTPS-прокси. Бот работает через polling. Одновременно запускайте только один polling-процесс с этим токеном.

1. Скопируйте `.env.example` в `.env`. Заполните BOT_TOKEN, BOT_USERNAME, APP_URL, DATABASE_URL, POSTGRES_PASSWORD, SECRET_KEY и ENCRYPTION_KEY. Для ENCRYPTION_KEY используется ключ Fernet. Пример публичного пути: `https://example.com/taskmaster/`.
2. Ограничьте доступ к `.env`: `chmod 600 .env`. Реальные секреты исключены из Git и сборочного контекста.
3. Задайте сеть HTTPS-прокси через PROXY_NETWORK и подключите к ней Caddy. Маршрут приведён в `ops/Caddyfile.example`.
4. Соберите основное приложение: `docker compose build api`.
5. Соберите распознавание: `docker compose build speech`. При первой сборке скачивается небольшая русская модель и устанавливается ffmpeg.
6. Запустите `docker compose up -d api bot worker speech`. База, Redis и миграции запустятся автоматически.
7. Проверьте `docker compose ps` и адрес `/taskmaster/health`. Ожидается `{"status":"ok"}`.

Если Telegram недоступен из Docker, настройте BOT_PROXY, например `http://host.docker.internal:2081`, для имеющегося HTTP-прокси сервера. Секретные заголовки и URL с токенами не выводятся в журналы HTTP-клиента.

Команды и кнопка меню устанавливаются ботом при запуске: `/start`, `/today`, `/tasks`, `/new`, `/cancel`. Основное управление через обычные сообщения и кнопки.

## Данные и обновление

Личные дела доступны только своему владельцу. Сервер проверяет Telegram initData и срок действия подписи. В обычном браузере доступен только экран входа. После часа работы Mini App нужно открыть заново из Telegram.

Миграция 0002 переносит старые задачи в личные списки автора и назначенного исполнителя, проверяя участие в исходном проекте. Исходные проекты, задачи, комментарии и файлы остаются в базе. Старые API сохранены для совместимости; проекты, Kanban, спринты, таймер и интеграции убраны из основного интерфейса.

Новые таблицы: personal_tasks, personal_reminders, personal_captures. Очередь голоса и расписание напоминаний хранятся в PostgreSQL и переживают перезапуск. Повторная обработка одного Telegram-сообщения не создаёт второе дело. Редактирование защищено версией.

Напоминания проверяются каждые несколько секунд. При недоступности Telegram используется повтор с задержкой. Пропущенные повторения объединяются в одно уведомление, следующее ставится на будущий срок. После 12 неудач доставка отключается и это видно в карточке. При блокировке бота уведомления также отключаются. Доставка не менее одного раза: при сбое между отправкой и фиксацией результата возможен повтор.

## Проверки

`npm ci --prefix frontend` и `npm run build --prefix frontend` собирают Mini App. Серверные тесты: `docker compose --profile test run --rm --no-deps test` с отдельной TEST_DATABASE_URL. Имя тестовой базы должно заканчиваться на `_test`; её содержимое пересоздаётся. Production-база не очищается.

Проверка перехода между миграциями: `docker compose --profile test run --rm --no-deps test python -m tests.check_migrations`. Она требует ту же отдельную тестовую базу. В CI проверяются сборка, права, задачи, разбор сроков, кнопки бота, напоминания, очередь голоса и миграция старых данных. Реальное распознавание проверяется отдельно в speech-контейнере.

## Резервное копирование

`sh ops/backup.sh /home/komarrick/taskmaster-backups` кратко останавливает API, bot, worker и speech, сохраняет dump базы, вложения и закрытую копию окружения, затем возвращает сервисы. Архив содержит секреты, храните копию вне сервера в зашифрованном виде.

Восстановление перезаписывает данные. Перед ним сохраните текущее состояние. Остановите пишущие сервисы, восстановите окружение, dump через pg_restore и архив вложений, выполните миграции и проверьте /health. ENCRYPTION_KEY нужно сохранить для прежних зашифрованных интеграций. Не используйте `docker compose down -v` для обычного обновления.

Подробности новой концепции: [docs/personal-dispatcher.md](docs/personal-dispatcher.md). Историческая архитектура первой версии: [docs/architecture.md](docs/architecture.md).
